## 3. Create original materials

Create six simple materials matching `manifest.json` and assign them by FBX slot name:

- Hood_GraphiteShell: dark polymer/painted shell, mild metallic value and satin roughness.
- Hood_OrangeTrim: restrained Foundryline accent.
- Hood_RubberPad: dark nonmetallic padding and headband detail.
- Hood_PivotSteel: metallic hinge/knob hardware.
- Hood_DarkFilterLens: very dark green/blue filter, non-emissive.
- Hood_LensCover: subtle reflective protective cover.

Use the manifest's linear colour, metallic and roughness values as the starting point. Do not turn the filter into a glowing display or make it transparent enough to expose the face through the closed shield. Check the layered cover/filter for flicker and stable reflections in native rendering. These materials and native `.uasset` packages have not been generated by this publication.

## 5. Remove the cap safely

The current forward/backward work caps intersect a realistic hood. When a welder equips it, build at most three shared transient no-cap outfit variants from the existing original part sets, filtering ONLY mesh names beginning `SK_Hat_`.

- Keep the same head, beard, body, clothes, employee ID and stable variant index.
- Never hide the whole head or entire person to remove a cap.
- Do not regenerate an outfit per frame or per employee.
- Do not save runtime merged skeletal meshes as editor assets; the editor ImportedModel is absent.
- On release/reassignment to another role, restore the exact normal outfit.
- Missing hood assets or a failed no-cap merge must leave the normal visible employee intact, with the hood hidden.

## 6. Head attachment and visor motion

Read these exact values from the manifest instead of eyeballing head alignment:

- Head bone: `head` on the evaluated Handyman poseable mesh.
- Head-relative translation, centimetres: `(14.558063928, -1.856296644, 0.001122955)`.
- Head-relative quaternion **XYZW order**: `(-0.025120771857, -0.706634613379, 0.025167143659, -0.706684572406)`.
- Neutral visor translation: `(0,0,0)` relative to the shared ear-hinge root.
- Native visor hinge axis: local +X.
- Closed:0 degrees. Raised:105 degrees.
- The corresponding Blender review angle is-105 degrees because of conversion handedness. Verify the actual native movement rather than changing signs based only on the Blender viewport.

Update headgear AFTER `CommitHandymanPose` so it follows real turns, leans and walking. Do not apply the profile's native facing correction twice or attach to an unrelated hat socket. Both native mesh origins are the same hinge; moving only the visor shell is sufficient.

## 7. Equip/raise/lower rules

| Employee state | Hood behavior |
| --- | --- |
| Assigned Welder, walking to work | Equipped, visor raised. |
| Assigned Welder, waiting for parts/output | Equipped, visor raised. |
| Assigned Welder, plant paused | Equipped, visor raised. |
| Actual welding, stationary and productive | Visor lowered. |
| Operator, driver or unassigned | Hood hidden, normal outfit restored. |

Assignment alone must not lower the visor. Candidate gating requires the real record to be Welder, assigned, not seated, actually working, Activity=Welding and not moving. Check pause/wait propagation in the current authoritative employee presentation before relying on those flags.

The candidate uses a short constant-speed cosmetic transition (720degrees/sec, approximately0.15sec for105degrees), not an instant snap. First equip starts raised. Weld progress, sparks authority, inventory and server work rate remain unchanged. Do not add fake replicated hood jobs or change save schema for a cosmetic target already derived from existing employee state.

## 8. Multiplayer, collision and lifecycle

- Existing company/plant/employee keys still select one person and one stable appearance.
- Co-op clients and late join derive the same equip/visor target from the authoritative employee record.
- Hood parts are non-colliding and cannot block forklifts, doors or employee navigation.
- Dedicated servers skip cosmetic meshes/outfit merges.
- Reuse the existing visual pool; hide/reuse on role change or culling without duplicate hoods.
- Import before starting the validation PIE session; restart PIE after a missing-asset test rather than assuming a failed one-time loader will discover a later import automatically.
- The current art has33,288LOD0 triangles. Add appropriate LOD/distance treatment before claiming large-crowd performance; no FPS guarantee accompanies these models.
